== pattern dfs
complexity: O(h+k) time · O(h) space
nudge: A search tree already encodes order: which way of walking it hands you its values sorted? And once the kth one has been reached, why keep walking at all?
-- step Start an in-order walk with a stack
1 stack, node = empty stack, root
  hint: What lets an in-order walk stop part way?
  why: An explicit stack of the ancestors still to visit; a recursive walk would have to unwind to the end.
2 while stack is not empty or node is not None:
  hint: When is there still something to visit?
  why: While a node is in hand or an ancestor is waiting on the stack.
-- step Slide down the left spine
3     while node is not None:
  hint: Where is the smallest value below this node?
  why: At the end of its left spine, so keep going left.
4         stack.push(node)
  hint: What do you do with each node you pass?
  why: Save it: it is visited after everything on its left.
5         node = node.left
  hint: Then?
  why: Step left.
-- step Visit, count, and turn right
6     node = stack.pop()
  hint: Which node comes next in sorted order?
  why: The one on top of the stack, the smallest not yet visited.
7     k -= 1
  hint: What does visiting a node do to k?
  why: One fewer value to go before the kth.
8     if k == 0: return node.val
  hint: When do you stop?
  why: When this is the kth value visited. The rest of the tree is never touched.
9     node = node.right
  hint: Where does the walk go after a node?
  why: Into its right subtree, which holds the next larger values.
10 return -1
  hint: What if the tree has fewer than k nodes?
  why: The walk ends without an answer, and the function still has to return something.
== pattern binary-search
complexity: O(n·h) time · O(h) space
nudge: The left subtree holds every value smaller than this node. If you knew how many there were, could you tell which side the kth smallest is on without walking in order?
-- step Descend from the root
1 node = root
  hint: Where does the search start?
  why: At the root, whose subtree holds every value.
2 while node is not None:
  hint: How long do you descend?
  why: Until the kth value is found; each step discards one side.
3     onTheLeft = size(node.left)
  hint: What do you need to know at each node?
  why: How many values are smaller than it within this subtree: the size of its left subtree.
-- step Pick a side
4     if k <= onTheLeft: node = node.left
  hint: When is the answer on the left?
  why: When at least k values sit there, the kth smallest is one of them.
5     elif k == onTheLeft + 1: return node.val
  hint: When is it this node?
  why: When exactly k - 1 values are smaller than it.
6     else: k -= onTheLeft + 1
  hint: What changes about k when you go right?
  why: The left subtree and this node are all smaller, so that many fewer remain to skip.
7         node = node.right
  hint: Then?
  why: The answer is among the larger values, on the right.
8 return -1
  hint: What if k is larger than the tree?
  why: The walk falls off the tree, and the function still has to return something.
-- step Count a subtree (in size(node))
9 return 0 if node is None else 1 + size(node.left) + size(node.right)
  hint: How many nodes does a subtree hold?
  why: None if it is empty, otherwise one for itself plus both sides.
